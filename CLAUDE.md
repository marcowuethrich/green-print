# Architectural Rules & Documentation

Before writing any code, proposing architectural changes, or adding new dependencies, you MUST execute the following steps:

1. **Start Here:** Read the file `docs/README.md`. This file serves as the table of contents for the entire project's documentation and Architecture Decision Records (ADRs).
2. **Navigate:** Based on the current task, use the `docs/README.md` index to find and read the specific, relevant ADR markdown files.
3. **Comply:** Ensure your proposed solution strictly adheres to the established patterns and constraints detailed in those documents.
4. **Conflict Resolution:** If your proposed solution conflicts with an existing ADR, you must explicitly state the conflict and stop to ask for developer confirmation before proceeding.
